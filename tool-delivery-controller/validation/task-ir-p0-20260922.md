# 架构调整 P0：Task IR / Contract / checkIds 对齐

本次按调整文档的分阶段建议落实 P0，维护实际 preset 中的执行代码。未改写模型选择策略或固定专业模型组合，未修改 agent.cordis.yml，也未操作 ~/.dsh-delivery 运行数据。

## 原始问题与处理

部署检查为空时，任务提出 `public-tests`，旧路径直接报 `Task checks must come from the deployment contract`。现在 context 预览与真实 start 使用同一个编译器：合法但未注册的 ID 记录为未验证文本，任务执行 checkIds 中只保留部署已注册 ID；命令文本、私自注册 checks、路径越界和 Task IR 内的计划/资源注入仍被拒绝。

Task IR 保存目标、约束、边界、可用实现工具与配置模型、检查、接口、验收和交付物，不生成步骤。IR 与编译事件持久化，Worker 接收同一上下文；Store 拒绝通过状态更新替换 IR。默认部署仍无测试，不会自动生成 public-tests、lint 或 build。

## 适用范围

交付状态 passed 表示执行及同步门禁完成，不能证明全部自然语言验收已通过。结果分别返回 acceptance、acceptanceComplete 与 root_acceptance_required；未知检查和文本条件始终可见。接口语义、幂等性和自然语言约束尚未自动编译成专用断言，不能宣称这些条件已被程序证明。
