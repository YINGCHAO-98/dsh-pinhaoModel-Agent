# 模型读写能力恢复

根因：tool-policy 对根模型隐藏执行工具，workspace.find 再拒绝根调用；specialists 默认工具缺少 write/edit 且所有工作区 readOnly=true，GLM 另有只读工具列表。该设计不符合用户要求的各模型具备读写能力。

修改：根模型 read/write/edit/glob/grep 以会话 cwd 为根，通过原生文件实现与 Seatbelt 执行；拒绝越界和符号链接路径，根 bash 仍不开放。所有专业角色工具至少包含 read/write/edit，作用域为各自隔离副本。Kimi 可新增文件，但若审查结束时原始输入发生修改或删除，执行路径拒绝质量报告。专业副本文件不会自动同步到用户项目，现有持久交付仍为报告 summary。简单文件任务允许根模型直接完成。

验证：77 项单元测试、5 项实际沙箱集成测试、5 项 DSH 原生集成测试通过（87 项）。外层沙箱不能嵌套 sandbox-exec；经自动审批在外层沙箱之外重跑两组集成测试后通过。覆盖根模型工具可见性及实际写/读/编辑、专业副本写入、越界与符号链接拒绝、质量输入篡改拒绝、原交付同步回归。

运行：桌面旧请求仍处于第 5 次重试；点击停止并通过 Harness 菜单重启，确认桌面恢复、旧会话不再运行。未发送新的在线模型请求，未重跑原动画，不宣称模型接口超时或流量保护已经修复。
