# 鹈鹕骑自行车案例：运行诊断（2026-09-21）

## 实测基线

原桌面会话首次生成约108秒，写文件成功后，后续模型请求连续300秒无流输出，重试4次后仍未结束，用户在26分19秒停止。当前超时规则下复现：生成127秒，写入成功，收尾请求120秒超时。

纯合成控制实验：短工具历史约2.42秒回复；长合成思考历史在 low/off 两种模式均120秒超时。实际请求保留模型必需的 reasoning_content；没有通过删除历史来修复。不能由此断言存在固定字节阈值或认定账号限额耗尽。

## 程序机制调整

1. 对明确的单HTML SVG/动画创建采用窄范围 off 计算策略；其他任务恢复原推理等级，用户明确选择更高等级时不覆盖。原始请求直写路径实测42.06秒完成（生成37.21秒、收尾4.57秒）。这不是跨模型严格性能基准，也不代表视觉质量等同参考。
2. 固定单HTML交付的实现工具限制为 read/write。成功写入目标文件后，依据真实工具调用回执撤销继续实现权限，自动转交检查和独立审查。写文件成功不等于通过交付。
3. 子任务错误保留真实上游原因。超时冷却2分钟、请求突发保护冷却5分钟；状态持久化，立即 resume、取消重建及重启不能绕过同一路由冷却；同交付第二次上游故障终止。正常120秒空闲超时不再按旧规则重试5次。
4. 修复沙箱接口冲突：文件工具可访问该任务自己已有的 scratch 临时目录，仍拒绝越界路径与符号链接。原审查花费大量时间重写无法写入临时目录的测试。
5. 给审查提供真实工作目录、临时目录、读取限制和运行环境信息，明确无浏览器能力、模拟DOM不能证明浏览器行为。完整报告保存，返回根模型的质量摘要排除原始 execution 和 tokenUsage，减少上下文重复。

## 发现的限制

完整流程基线存在重复自检、隐藏上游错误和恢复重试放大。首次自动移交版本在57秒成功写入并进入Kimi，但审查因临时目录冲突及不断调试自制DOM测试耗尽5分钟。冷却实际阻止了随后resume重启审查。

直接快速版本能运行，但视觉上脚与踏板连接仍有瑕疵，不能承诺“off就有同等质量”。正式质量判断还需要实际浏览器观察；自动结构/语法检查不覆盖审美。

自动审批拒绝了向模型服务重放完整捕获会话，原因涉及原始会话数据外发；已改用完全合成的长历史做独立实验，没有绕过拒绝。

## 进一步复现

第二次完整运行：初稿43秒，Kimi审查约232秒，并真实拒绝了不符合踩踏要求的刚性腿部动画。修复请求输入因包含完整审查execution膨胀到100470字节，120秒无输出；随后主模型输入121120字节，最终测试时限取消。已将修复输入和根模型质量结果均改为受限摘要，完整证据仍在报告和控制器状态。

浏览器还实见CSS旋转覆盖SVG定位导致车轮飞离车架；新增固定检查后，用该真实失败文件验证得到 SVG_TRANSFORM_ANIMATION_CONFLICT，修复为外层定位/内层旋转的测试通过。此规则不覆盖所有旋转中心、腿部几何和审美问题。

## 最新端到端链路与视觉结果

最新运行 oYj6M5：单HTML实现40.67秒；约54秒时已完成写入并进入Kimi。Kimi独立审查约267秒后返回passed，控制器完成检查与同步。该运行使用了根模型质量摘要、scratch别名和SVG覆盖检查；修复输入摘要和DSH_WORKSPACE环境变量随后由回归测试覆盖。

但浏览器人工观察仍发现腿部绕错误中心旋转、与身体/踏板分离，Kimi静态检查漏检。本轮交付状态passed只代表现有程序检查与静态审查通过，视觉验收为未通过，不能宣传为达到分享案例质量。当前preset尚无真实浏览器渲染/截图工具；GLM能分析传入图片，但不能自己生成浏览器截图。局部静态规则能挡住特定缺陷，不能替代视觉验收。未把手动修改测试产物冒充模型生成质量。

回归：88项单元/配置/超时测试通过；11项真实DSH与macOS Seatbelt集成测试通过。测试包含真实回执交接、交接后调用拒绝、冷却持久化与绕过拒绝、scratch访问/越界/符号链接拒绝、修复输入精简和已复现SVG冲突拒绝。
