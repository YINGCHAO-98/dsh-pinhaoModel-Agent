# 鹈鹕骑车单 HTML 验证（2026-09-23）

测试输入原文：`创建一个单html，内容是SVG 绘制一个鹈鹕骑自行车的2D动画。`

## 归因

- 模型侧：原会话中的 Kimi K2.8 在输出预算内没有产生工具调用；本次实跑也多次出现只读调用后长时间没有写入。恢复 Worker 曾输出重复文档，并在一次定点修复中遗漏了鹈鹕、自行车和控制按钮。
- Harness 侧：原先缺少及时发现无写入的进度期限、受控模型恢复，以及足以拒绝重复文档和大规模结构丢失的验收门禁。模型错误本身不能解释错误结果仍被标成 `passed`。

## 已落实的通用机制

- 单 HTML Worker 的首工具/首有效写入期限；零写入超时或输出耗尽后有界重试和受控恢复模型。恢复沿用同一写入范围、隔离副本和验收合同。
- 产品设计文本不再扩大强制检查清单；Worker 只收到原始目标、用户合同和简洁设计指导，检查命令仍由控制器持有。
- 单 HTML 检查拒绝重复或错序文档、尾随内容、SVG 标签不平衡、外链和 JavaScript 语法错误。
- 更新已有单 HTML 时，严重的可绘制/交互元素和具名类同步丢失会产生 `HTML_STRUCTURE_REGRESSION`，阻止同步。该门禁以结构异常为信号，不宣称理解任意页面语义。

## 运行证据

- 实模型端到端运行：`pinhaomo-live-rKyypn`，原始任务的第一轮交付通过。独立审查指出背景滚动循环不连续，随后自动发起修复。旧版验收错误地放过了只剩背景的修复结果；此结果复现了新增门禁的拒绝路径：可绘制/交互节点 197→70，保留具名类 5/18。
- 单元测试 163 项通过；DSH 宿主集成 14 项通过；沙箱集成 6 项通过。新增的拒绝路径测试确认被截断文件不会同步到项目。
- 本目录中的 `pelican-bicycle.html` 由首轮完整产物定点修正山、树、云的图块周期；保留鹈鹕、自行车、标题、按钮和道路动画。单 HTML 结构/JS 检查通过，结构回归检查通过。
- Chrome DevTools 实测：SVG 场景、鹈鹕主体、两只车轮、四个周期图层均存在；相隔 300ms 的画面不同；暂停/继续按钮生效；无页面 JavaScript 异常。`preview.png` 是浏览器截图。
