# 评价制度（v2：按已确认流程验收）

撤回 v1 的 45/100 总分、任意耗时门槛和成熟度/不及格判断。旧证据文件保留为历史，其中可复现的缺陷与测试记录仍有效；不得再以旧总分给当前 agent 定级。

评价对象为本 preset 在用户确认工作环境中的实际表现，不按模型或工具数量加分。每项记录“已验证 / 存在失败 / 未验证”、适用版本、验收条件和证据；未知不算失败。没有约定的权重、样本量和合格线，不自行给总分或判不及格。

| 评价维度 | 验收内容 |
| --- | --- |
| 任务隔离与上下文 | 独立副本互不污染；任务具备必要接口、依赖、修改范围与验收条件；不过量传播其他会话。 |
| 子任务交付可靠性 | 实际产物与输入版本、验证证据绑定；越权修改、未完成或篡改产物不能作为通过结果导入。 |
| 总 agent 集成 | 能汇入已验收子任务；对组合结果重新测试、审查和修复；不把各自通过视为整体通过。 |
| 自动同步与冲突处理 | 整体验收后自动同步并复核；保留并行成果；可合并变更自动处理，需取舍的冲突提供具体证据；旧决定不能覆盖新版本。 |
| 可追溯性与实际效果 | 记录执行、失败、修复、集成、同步及限制；区分真实模型效果、fixture 机制测试和未经验证的假设。耗时、Token 与返工用于观察，不擅设不及格线。 |

评估先声明任务范围与验收条件，再报告结果。行为修改只重跑相关检查；大规模真实模型评测不作为每次配置修改的隐含要求。评分权重或效果阈值若需引入，应先与用户确定，再冻结执行，不能事后调整以制造好成绩。

当前已知范围：控制器实现 partial/project 模式、同一总会话下 sourceDeliveryIds 汇总、三方合并、冲突决定版本校验、同步日志与同步后检查。新增 tasks 登记固定父子任务、依赖和修改范围；必需子任务缺失或未通过时状态机阻止整体交付。冲突决定通过宿主用户交互服务直接取得，模型传入的选择被拒绝。外部工具适配器尚未配置；跨独立总会话共享产物尚未开放；不宣称已经支持全部外部工具和跨会话共享。独立进程不遵守锁时，普通文件系统不提供多文件全局原子事务，必须保留冲突检测与事后复核。

旧媒体输入反例仍待单独修复，见 [媒体输入反例](validation/agent-score-v1-20260920-probe.mjs)；撤回旧分数不等于消除该缺陷。

## 依据与证据

本制度以 [工作环境与交付约定](WORKFLOW.md) 为依据，是评估规则，不是控制器自动评分或运行时审批机制。删除维护用 AGENTS.md 不影响本制度的保存与查阅。

- [验证说明](VALIDATION.md)：区分机制测试、真实模型样例与各轮验证范围。
- [项目交付验证记录](validation/project-delivery-20260920.json)：对应验证时的文件指纹与测试范围。
- [已撤回的 v1 评分记录](validation/agent-score-v1-20260920.json)：只保留历史证据，不沿用其总分或成熟度判断。

历史记录中的路径和指纹描述当时版本，不因文档迁移而改写为当前版本。最新规则以本文件为准。
