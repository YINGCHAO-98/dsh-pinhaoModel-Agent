# 工作环境与交付约定

- 当前是多 agent 工作环境。总 agent 汇总并对最终集成结果负责；子 agent 对其任务范围内的交付负责。
- DeepSeek 负责总编排；交付先由 MiniMax 输出产品设计方案，再由 Kimi K2.8 优先实现。连续无有效写入时，控制器有界调用一次配置的恢复 Worker。方案标记为高风险时由 Kimi K2.7 独立验收；GLM 负责静态视觉、豆包负责动态媒体理解，Seedream/Seedance 分别负责图像/视频生成（以实际适配器可用状态为准）。设计成功、完整性校验和高风险验收均在控制器执行路径生效。
- 分步交付使用独立副本，只传递该任务必要的目标、接口、依赖、修改范围和验收要求，不灌入其他 agent 的完整会话。产物必须附输入版本、实际改动和验证证据，供总 agent 汇总。用户明确取消验证的独立单 HTML 不属于分步交付，必须记录 `assurance=unverified` 和 `verified=false`，不能伪造验证证据。
- 整体项目交付先在沙盒完成集成、测试、验收和修复，通过后直接同步当前项目及已接入的相关工具，并核验同步结果；无需再次请求例行确认。
- 子任务通过不能替代整体集成验收。合入其他 agent 的结果后必须验证组合结果；总 agent 不能只汇总口头“已完成”。因此无验证模式拒绝子任务、产物导入和多模块工程。
- 同步以原始版本、交付版本和当前项目做三方比较。保留其他 agent 的改动，自动合并兼容修改；需要用户取舍的冲突才询问，必须给出具体冲突与选项。用户决定绑定当时版本，版本变化后重新检查。
- 普通测试失败、可自动解决的合并问题继续修复；需求矛盾、行为取舍不明才向用户提问。预算耗尽、环境故障应准确报告，不能假称成功，也不能增加没有必要的审批。
- 文件同步和外部工具操作分别记录。外部操作须有真实适配器、目标范围、幂等/重试规则及结果核验；未接入不能写成“已同步”。
- 上述可执行约束必须在控制器、状态机和工具权限中生效；Skill 只说明如何使用。
