# 多模型编排

以最短可靠关键路径为目标，而不是追求 Agent 数量。
当任务覆盖产品定义、方案设计、代码实现和功能测试的完整生命周期时，另外加载 `software-delivery-harness`，
使用动态工作流引擎执行结构化门禁，不用普通多轮对话模拟完整研发流水线。

## 规划

1. 明确最终交付物、约束和验收条件。
2. 先判断主能力域。普通问答和简单操作由 DeepSeek 直接完成；单一能力任务最多委派一个专业模型。
3. 只有最终交付跨越两个或以上能力域，且每个节点都能产生不可替代的独立结果时，才拆为多模型 DAG。
4. 多步骤、多文件、自测、错误重试、单张图片、单篇文档或单个网页都不自动构成多模型任务。
5. 标明依赖；无依赖节点同时启动，有依赖节点等待必要输入。
6. 默认最多同时运行三个专业子 Agent。

## 唯一路由

- DeepSeek：普通问答、产品定义、用户流程、技术方案、架构、规格、实施计划、代码实现、调试、总调度、结果整合和最终验收。
- Kimi K2.8 Preview：仅负责超长上下文、多文档交叉阅读、长报告提炼、研究和复杂资料汇总。
- Kimi K2.7 Code：仅在完整研发工作流、发布级或高风险任务中负责独立功能测试、回归检查和质量门禁。
- MiniMax M3：品牌文案、广告标语、短视频脚本、分镜和创意变体。
- GLM 5.3 Flash：静态图片、Logo、UI、图表和视觉文档分析。
- Seedream 5.0 Pro：通过 `ark-media-generation` 和 ArkCLI 生成或编辑图片。
- Seedance 2.5：通过 `ark-media-generation` 和 ArkCLI 生成视频。
- Doubao Seed 2.0 Lite：音频、视频、字幕和音画同步理解。

主责与备选模型不得并行执行同一任务。同一个产物不得让多个模型各做一份。
不创建可用性探测、诊断 ping、纯状态检查或没有独立交付物的子 Agent。
用户已经给出清晰需求时，不为补充 PRD、方案或视觉分析而额外调用模型。

## 交接与验收

每个委派包含目标、必要上下文、输入绝对路径、输出要求、约束和验收标准。子 Agent 返回：

- 状态
- 核心结果
- 产物绝对路径
- 验证证据
- 限制和未解决问题

长内容写入文件，下游仅接收必要摘要和路径。根 Agent 在最终交付前核对全部验收条件，不把子 Agent 的自评直接当作验收结论。

任一节点失败时只阻断依赖它的节点。鉴权、权限、模型未开通或参数不支持错误不重试；临时网络、限流或超时最多重试一次，随后按根 Persona 的回退策略继续可行交付。
