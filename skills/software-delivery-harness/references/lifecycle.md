# 研发生命周期与门禁

## 1. 产品定义

输入是用户原始目标和已有项目事实。产出 PRD，至少包含范围、非目标、用户流程、边界条件和可测试的验收条件；
UI 类产品还要包含信息架构、关键界面状态和交互规则。

门禁：

- 必须有 PRD 产物绝对路径。
- 验收条件必须可观察，不得只写“体验良好”。
- 存在会实质改变范围的用户决策时，状态为 blocked。

## 2. 方案设计

以 PRD 和项目现状为输入，产出技术方案。覆盖模块边界、数据流、接口、状态、错误路径、迁移或回退、实施步骤和测试策略。

门禁：

- 必须有方案产物绝对路径。
- 方案必须与 PRD 验收条件对应。
- 高风险假设必须被验证或明确标记。

## 3. 实现

以已通过门禁的 PRD、技术方案和必要视觉产物为输入。实现 Agent 进行最小而完整的变更，执行实现阶段的基础验证。

门禁：

- 必须返回实际修改文件的绝对路径。
- 必须记录执行过的验证命令和结果。
- 实现 Agent 的成功只表示“可进入独立测试”，不表示最终验收通过。

## 4. 独立质量门禁

测试 Agent 读取 PRD、方案、变更和现有测试，逐项验证验收条件，并执行与风险相称的回归检查。

门禁：

- passed 必须包含可复查的命令、输出或测试报告。
- failed 必须包含可重现的最小问题和期望行为。
- blocked 必须说明缺失的环境、权限或依赖。

## 5. 修复与重测

把测试失败的最小证据交给实现 Agent，不重新传递全部历史。每轮修复后由质量 Agent 重新执行相关测试和必要回归。最多两轮。

## 6. 最终验收

根 Agent 核对用户目标、PRD、方案、变更、质量门禁和未解决风险。只有适用的验收条件全部有证据时才宣告完成。
