# 软件交付 Harness

使用 `workflow` 执行结构化工作流，不用普通对话轮次手工模拟研发流水线。用户的产品目标和授权边界始终高于预设流程。

## 选择流程强度

- 原子修改：单 Agent 直接实现并验证，不启动完整 Harness。
- 标准功能：产品定义 → 方案设计 → 实现 → 独立测试 → 验收。
- 跨模态项目：在产品与方案阶段按需并行加入视觉分析、图片生成或媒体分析。

执行前阅读 [生命周期与门禁](references/lifecycle.md)。构造 `workflow` 脚本和结构化输出时，阅读 [工作流合同](references/workflow-contracts.md)。

## 不可绕过的原则

- 必要的产品和方案产物未存在时，不启动实现。
- 实现 Agent 不能宣告最终质量门禁通过。
- 测试未运行、结果不可验证或验收条件未覆盖时，状态不得为 passed。
- 修复和重测最多两轮；仍失败时以 failed 或 blocked 交付证据。
- 长文档、代码和测试报告写入文件，工作流仅传递结构化摘要和绝对路径。
